# Task — theme the 94 shows whose episodes sit in no arc

Autonomous brief. Self-contained: assume no memory of the session that wrote it.
Pure `python3` (standard library only — **no pip, no venv**). The model is reached only
through Claude Code `Workflow` subagents.

**Model ceiling: Sonnet. Do not use Opus for any subagent.**

## Why this exists

`approaches.py` (`A8-cascade`) groups episodes into story arcs from title grammar. It covers
221 of 315 shows. It cannot touch anthologies — shows where every episode is a different
story — because there is no run to detect.

But those shows are not unstructured. Swindled's Ford Pinto, OceanGate and ValuJet episodes
are one kind of story. A model can find that when the title names the subject.

**Swindled is the worked precedent.** 14 themes over 153 episodes, audit passed, 76%
agreement across two labelling runs. Read `curation/arc-bakeoff/episode-themes/swindled.json`
before starting — that file is the output shape to reproduce.

## The shows — 94, about 19,300 episodes

Every show with **≥40 full episodes in no arc**, minus the exclusions below. Regenerate the
list rather than trusting a paste; the selector belongs in `build-episode-themes.py`.

**Exclude only these 9 — they resolve to a different show than their metadata claims:**
`broken-record` (a teenager's music vlog, not Rick Rubin's), `hit-parade` (a Spanish radio
chart show), `homecoming` (a SoundCloud self-help podcast), `gun-machine`, `animal`,
`earshot`, `shift`, `startup`, and `making-oprah` (byte-identical feed to `making-obama`).

**Do not gate on title shape, and do not gate on anything else.** Every one of the 94 runs.

An earlier draft required an extractable subject slot — the `The Descent (OceanGate)` shape —
and cut Radiolab, 99% Invisible, Criminal and Song Exploder. Wrong twice over. Radiolab's
*Antibiotic Apocalypse* and 99pi's *The Em Dash* have no subject slot because the title **is**
the subject, and they need less world knowledge than Swindled, not more.

And the deeper mistake: treating the corpus as all the data there is. **It is not. Fetch the
descriptions.** See step 0.

## Step 0 — fetch descriptions first

`curation/feeds/*.json` holds six fields per episode and no description, because
`scripts/fetch-atlas-feeds.py:117` never asked for one. That is a limitation of one script,
not of the data. **Every feed serves descriptions and they are excellent.**

Verified on the three worst-scoring shows — 40 of 40 items carried a real description on
each:

> **125 Acres** *(Criminal, a 14-character title)* — "George Dinning was emancipated in 1865,
> when he was 10 years old. By the time he was in his mid-thirties, he'd bought the land on
> which he had been enslaved. Years later, 25 white men approached…"

Write **`scripts/fetch-feed-descriptions.py`** — stdlib only:

- Read `feedUrl` from `curation/feeds/<slug>.json` for each of the 94.
- Reuse `fetch-atlas-feeds.py`'s `http_get`, its `safe_fromstring` XXE guard (**not
  optional**), its retry logic and its 0.6s politeness delay.
- Per item take `description`, else `itunes:summary`, else `content:encoded`. Strip HTML,
  unescape entities, collapse whitespace, truncate at **300 characters** — the samples show
  the topic lands well inside that.
- Write a sidecar: `curation/arc-bakeoff/descriptions/<slug>.json` =
  `{slug, fetchedAt, episodes: {guid: description}}`. **Sidecar, not a corpus edit** —
  `curation/feeds/` is gitignored and regenerated by a script that skips existing files, so
  editing it would make the corpus non-reproducible.
- Gitignore the sidecar directory. These are third-party copyrighted blurbs.
- ~94 requests, a couple of minutes. Resumable: skip a slug already on disk.

Then **give the model the title and the description together.** With descriptions in hand
there is no thin-title tier and no show that "may produce nonsense" — `transfert`'s French
narrative titles and `within-the-wires`' in-universe titles both come with real synopses.

Note the live feeds have moved past the snapshot (Radiolab: 663 items live vs 659 stored).
Match descriptions to episodes by guid and accept that a few will not match; that is fine.

## The one change from the Swindled run

Swindled used a hand-written extractor in `SHOWS` in `build-episode-themes.py` — a regex to
strip `S10 Ep141:` and take the trailing parenthetical. **28 shows cannot each get bespoke
config.**

Replace it with a generic best-effort extractor: try trailing parenthetical (rejecting one
that contains `Chapter|Part|Pt|Episode` + digits), then `Name: Subject`, then `Name | Subject`,
then `Artist – Song`, else the whole title. **Pass the model both the raw title and the
extracted guess.** For a show like Radiolab the guess will just be the whole title, which is
correct — the title is the subject. A bad extraction costs signal on one row rather than
poisoning the show.

Keep the existing dedupe: drop a re-airing when the original is present, and prefer the
original's guid.

## Pipeline, per show

Three passes, matching `episode-theme-workflow.mjs`, batched larger for scale:

1. **Open code** — `model: 'sonnet'`, **80 episodes per call** (smaller than Swindled's 100
   because each row now carries a description). Free-form theme phrase per episode, no fixed
   vocabulary. Let categories emerge.
2. **Consolidate** — `model: 'sonnet'`, one call over every raw label. Produce 10–16 themes,
   each with a slug, name, one-sentence definition, and `mapsTo` pointing at one of the 30
   show-level themes in `curation/catalog/themes.json` (empty string when none fits).
3. **Assign** — `model: 'haiku'`, 80 per call. One primary + up to two secondary from the
   frozen vocabulary, plus confidence `high|medium|low`.

**Skip the two-run agreement pass for the bulk** — it doubles assign cost. Run it on a
6-show sample, and **always include `radiolab` and `99-invisible` in that sample**. They are
the shows whose titles state a topic rather than name an entity, so they are the ones where a
vague, non-discriminating vocabulary is most likely and least visible to the audit. Low
agreement there is the signal that the vocabulary is not cutting anything.

Roughly 241 + 94 + 241 + 12 ≈ **590 agents** for ~19,300 episodes. Far above the normal
guideline; that is expected for an overnight job, and still under the 1,000-agent cap. If it
would exceed the cap, split the show list across two runs rather than trimming shows.

## Audit — per show, non-blocking

Same thresholds as Swindled, in `build-episode-themes.py`:

- Vocabulary size 10–16.
- No theme under 3 episodes.
- No theme over 35% of the show.
- Zero out-of-vocabulary labels; exactly one primary each; max two secondary.

**A failing audit flags the show and the run continues.** Nothing halts.

Watch for the failure Swindled hit: a **junk-drawer category defined by what it is not**.
Swindled's `swindlers-and-grifters` was "an individual con artist… without a fund, a company,
or a religious front", and it swallowed everything ambiguous — 9 of the 17 low-confidence
episodes plus 4 of the 5 most-disagreed boundaries. If a definition is phrased mostly as
exclusions, say so in the recap.

## Standing decision

**Flag and categorize. Never drop.** A low-confidence or audit-failing result is marked, not
removed. Nothing is deleted from the corpus or from any show's output.

## Output

- `curation/arc-bakeoff/episode-themes/<slug>.json` per show — same shape as
  `swindled.json`: `{slug, title, models, vocabulary[], episodes[], agreement{}}`. Committed.
- `curation/arc-bakeoff/episode-themes/_run-report.json` — committed. Per show: episodes
  in/out, vocabulary size, confidence spread, audit pass/fail with reasons, junk-drawer
  suspects (any theme whose definition reads mostly as exclusions), and the sample agreement
  numbers. This is the recap. **It is data, not a document.**

**Everything this run produces has to land in the workbench, browsable and filterable.**
That tool exists to understand the shape of the catalog that ships with the app. Analysis
that sits in a JSON file, or in a standalone HTML page nobody opens, is not doing its job.

Run `python3 scripts/serve-catalog.py --tailscale`; the UI is `tools/catalog-browser/`.

`build-catalog-index.py` already folds per-show theme data into `catalog-index.json`. Extend
it so every signal this run produces reaches an object you can browse:

| Signal | Attached to | Surfaced as |
|---|---|---|
| Assignment confidence | episode | badge on the row; **Model confidence** facet (exists, currently covers only Swindled) |
| Theme confidence spread | theme | counts on the theme card |
| Junk-drawer suspect | theme | badge, and a facet to find them across shows |
| Audit pass/fail + reason | show | badge on the show card, and a facet |
| Two-run agreement | show | shown where the Swindled number already is |
| Vocabulary size | show | on the show |

So the questions the workbench should answer after this run:

- *Which shows failed audit?* → a facet.
- *Which themes are junk drawers?* → a facet, across all 94 shows.
- *Show me every low-confidence episode label* → the existing confidence facet, now
  meaningful because it covers 94 shows instead of one.
- *What did this show's vocabulary come out as?* → open the show.

A run-level summary — shows processed, episodes labelled, failures — can go at the top of
the **System** view. Keep it to numbers. The per-object flags above are the point; the
summary is a footnote.

Match the existing style: `tools/catalog-browser/app.css` tokens, no framework, no build
step, both themes, works at phone width. Do not restructure the navigation.

## Context
